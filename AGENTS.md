# AGENTS.md — CodeStream (codestream.co.za)

Guidance for AI coding agents working in this repository.

## What this repo is

**CodeStream Systems (PTY) LTD** static marketing website for `codestream.co.za`.

- **Product type:** brochure / advertising site only
- **Not** a product app: no auth, no user accounts, no login/register, no backend API in this repo
- **Deploy target:** Azure Static Web Apps (GitHub Actions → `dist/`)

Positioning to preserve in copy and UI:

1. Azure / custom software / systems architecture specialists  
2. Fully **AI-embracing** delivery — AI used aggressively across development, delivery, and support  
3. Tagline: **Dream, Design, Develop, Deliver**  
4. Legal entity details in the footer (always visible)

## Stack

| Layer | Choice |
|--------|--------|
| Runtime UI | React 19 + TypeScript 7 |
| Build | Vite 8 + a prerender pass (`scripts/prerender.mjs`) |
| Routing | TanStack Router (file-based routes under `src/routes/`) |
| Styles | Tailwind CSS v4 (`src/styles/app.css`, `@tailwindcss/vite`) |
| Motion | Motion (`motion/react`, the renamed Framer Motion) |
| Icons | lucide-react |
| Class helpers | `clsx` + `tailwind-merge` via `cn()` in `src/lib/utils.ts` |

Do **not** reintroduce Next.js, the old Tailwind UI “Pocket” template, MediatR-style app shells, or auth pages.

## Commands

```bash
npm install
npm run dev       # Vite dev server
npm run build     # tsc --noEmit && vite build → dist/
npm run preview   # serve production build
```

Prefer verifying with `npm run build` before claiming work is done.

## Content rules

- **Edit marketing copy and lists in `src/content/`**, not buried in JSX, when possible:
  - `site.ts` — nav, hero copy, client names, legal entity, contact placeholders
  - `services.ts` — Dream / Design / Develop / Deliver

  - `projects.ts` — selected work, one row per engagement
  - `tech.ts` — capability groups and the contact-section copy

- Client logos and project claims are business IP; keep tone professional; do not invent new clients or case studies without user direction.

## Design / UX conventions

The palette, type scale and motion system are specified on the design canvas and
mirrored in `src/styles/app.css` under `@theme`. Do not introduce colours or sizes
outside those tokens.

| Token | Value | Use |
|---|---|---|
| `slate-deep` | `#45616c` | dark section ground |
| `coral` | `#cb8067` | accent: buttons, rules, numerals, the contact block |
| `wheat` | `#eed9b5` | labels and numerals on dark |
| `aqua` | `#a6c6c3` | quiet tint on dark |
| `paper` / `band` | `#faf8f4` / `#f0ece2` | light grounds |
| `body` / `on-slate` | `#556168` / `#dde6e8` | the only two body-text colours |

- Everything sits at low chroma. Coral and wheat are never body text.
- Sections alternate dark and light so no two adjacent ones share a ground. Coral
  fills exactly one section — the contact close.
- Type is one family: Archivo, widened to 106% at weight 700 for headings
  (`.type-display`, `.type-title`), normal width for body. Newsreader italic is for
  asides only; IBM Plex Mono for labels (`.type-eyebrow`, `.type-label`). Headings are
  sentence case. **Inter is deliberately retired.**
- Square corners. No border radius, no shadows, no gradients — depth comes from the
  colour blocks and hairline rules.
- Motion is three primitives only — rise, wipe, fade — via `<Reveal>`
  (`src/components/ui/Reveal.tsx`), each playing once on first entry into the
  viewport. Stagger: 90ms hero, 80ms cards, 40ms table rows, never past ~420ms.
  `prefers-reduced-motion` short-circuits `Reveal` to a plain element.
- The hidden starting state lives in `Reveal`, never in the stylesheet — the
  prerendered HTML must render at full opacity if the bundle never arrives.
- Sticky-free header with section anchors + **Start a conversation** (mailto). Never
  add Sign in / Sign up.
- Hit targets are never under 44px. Prefer accessible markup: real `alt` text,
  semantic sections, focus-visible styles.
- Avoid fintech-template leftovers (fake stock charts, app-store buttons, pricing
  tables, joke FAQs).

## Routing

- File-based routes in `src/routes/`; TanStack Router plugin regenerates `src/routeTree.gen.ts`.
- Primary UX is a **single landing page** with hash anchors (`#services`, `#ai`, `#work`, etc.).
- Keep the site static-friendly for Azure SWA (`public/staticwebapp.config.json` navigation fallback).

## Deploy

Workflow: `.github/workflows/azure-static-web-apps-icy-hill-047cbbb03.yml`

- Build: `npm run build` (typecheck → client build → SSR build → prerender)
- Output: `dist`
- `npm run build` prerenders every route in `ROUTES` (`scripts/prerender.mjs`) into
  static HTML so `dist/index.html` ships the real page rather than an empty shell.
  The browser hydrates that markup. **If you add a route that should be crawlable,
  add it to `ROUTES`.**
- The prerender step fails the build if a route renders empty — that is deliberate,
  do not soften it.
- Do not switch back to Next `build_export` / `out/` without an explicit product
  decision.

## Out of scope (unless the user asks)

- Authentication, dashboards, CMS, blogs  
- Backend contact forms / CRM (mailto only unless requested)  
- Multi-language  
- Git worktrees for routine feature work (use normal branches)  

## Working agreements for agents

1. Prefer small, focused changes that match existing patterns.  
2. Do not commit, push, or open PRs unless the user asks.  
3. Do not create git worktrees unless the user explicitly requests them.  
4. After substantive UI/stack changes, run `npm run build`.  
5. Keep AI messaging confident and professional — process advantage, not sci-fi hype.  
6. When adding sections, wire them into `src/routes/index.tsx` and the Header nav if they should be discoverable.
